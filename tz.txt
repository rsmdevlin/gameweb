# ЧТО СДЕЛАТЬ СЕЙЧАС

Не пытайся сразу создать 20 карт и 100 механик.

Сделай **один очень качественный Vertical Slice**, который показывает конечное качество игры.

Игровой flow:

LOGIN
→ MAIN MENU
→ SERVERS
→ CREATE/JOIN SERVER
→ LOBBY
→ START
→ UNREAL 3D GAME
→ ROUND
→ RESULT
→ LOBBY

# 4. UNREAL GAME

Сделай полноценную 3D сцену.

НЕ использовать зелёную плоскость и набор кубов как финальный результат.

Нужна атмосферная карта.

Например:

## ABANDONED HOTEL

Небольшая, но детально сделанная карта:

* lobby;
* corridors;
* rooms;
* furniture;
* reception;
* kitchen;
* storage;
* stairs;
* basement;
* декоративные объекты;
* believable lighting.

Главное — не размер, а качество.

# 6. PROP HUNT

Сделать реальный игровой vertical slice.

Минимум:

HUNTER
VS
PROPS

Сервер определяет роли.

Например:

4 players:
1 Hunter
3 Props

---

# 7. PROPS

Использовать реальные 3D assets карты.

Минимум 8–12 разных типов:

Chair
Table
Box
Barrel
Lamp
Plant
Bin
Crate
Bucket
Bottle
etc.

Prop игрок может выбрать объект и превратиться в него.

После transformation:

Character → Prop

Prop должен:

* двигаться;
* вращаться;
* прыгать;
* прятаться;
* синхронизироваться с другими игроками.

---

# 8. HUNTER

Hunter должен иметь оружие/инструмент.

Минимальный gameplay:

* aim;
* shoot;
* hit detection;
* damage;
* kill;
* reload/cooldown.

Если Hunter стреляет в обычный объект — получает penalty.

---

# 9. ROUND

Сделать полноценный round loop:

PREPARATION
→ HIDING
→ HUNT
→ ROUND END

Например:

30 sec preparation
20 sec hiding
5 min hunt

Таймер должен быть серверным.

---

# 10. WIN CONDITIONS

Props:

выжить до окончания времени.

Hunters:

найти и уничтожить всех Props.

После раунда:

WINNER
SCORE
KILLS
SURVIVAL TIME

Затем обратно в lobby.

---

# 11. MULTIPLAYER

Это должен быть настоящий multiplayer.

Два разных браузера должны подключаться к одному server/game session.

Игроки должны видеть:

* друг друга;
* movement;
* rotation;
* animation;
* transformation;
* attacks;
* damage;
* death.

Не fake players.

Не локальная имитация.

Не client-only multiplayer.

Использовать server-authoritative архитектуру.

---

# 12. BACKEND

Существующий Node/WebSocket backend не переписывать без необходимости.

Интегрировать Unreal с ним.

Backend отвечает за:

* auth;
* users;
* rooms;
* lobby;
* matchmaking/room state;
* chat;
* persistence.

Realtime gameplay state должен быть согласован с Unreal multiplayer architecture.

Если для Unreal нужен отдельный dedicated game server layer — добавь его архитектурно правильно, не ломая существующий backend.

---

# 13. PIXEL STREAMING

Подготовить Unreal под Pixel Streaming.

Браузер должен получать Unreal через WebRTC.

Сделать web integration:

Browser
→ Pixel Streaming
→ Unreal

Аутентификация/room information должны интегрироваться с нашим backend.

Не делать вид, что Pixel Streaming работает, если он реально не настроен.

# 14. MOBILE

Мобильный пользователь должен получить **реально адаптированную игру**, а не уменьшенную desktop-версию.

Сделать mobile-specific:

* UI;
* touch controls;
* virtual joystick;
* camera touch control;
* attack button;
* jump;
* ability;
* interact;
* sprint;
* responsive HUD.

Кнопки должны быть удобными для пальцев.

Учитывать разные размеры экранов.

Если используется landscape для gameplay — сделать полноценную landscape-ориентированную версию с адаптированным интерфейсом.

Главное: мобильный игрок должен реально иметь возможность пройти весь Vertical Slice и играть в multiplayer.
